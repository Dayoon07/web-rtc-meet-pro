# 운영 전 법적 점검표 (MQ)

> 개발자가 코드와 법 조항을 맞춰 보고 정리한 점검표입니다. **법률 자문이 아니므로**, 정식 운영 전에
> 완성된 이용약관·개인정보처리방침을 변호사나 한국인터넷진흥원(KISA) 무료 상담
> (개인정보보호 종합포털 privacy.go.kr, ☎ 118)으로 한 번 확인받으세요.

## 그 밖에 이번에 넣은 것

- **관리자 접속기록** (안전성 확보조치 기준 제8조): 관리자 API 를 부를 때마다 누가·언제·어디서·무엇을 남김 (`admin_access_logs`, 2년 보관, 관리자 화면에서도 수정 불가).
- **국외 이전 고지**: 구글 로그인, 브라우저 음성 인식(Chrome·Edge → Google), Claude API(쓰도록 설정한 경우) 를 처리방침 7번에 적음. Ollama(자체 서버)로 하면 회의 내용은 국외로 나가지 않음.
- **멤버 초과 요금 동의**: 소유자가 안내를 보고 체크해야 켜지고 동의 시각을 남김. 결제 3일 전 금액 안내 메일.

## 운영자가 할 일 (코드로 할 수 없는 것)

1. 사업자등록, **통신판매업 신고**, `deploy/.env` 의 `VITE_COMPANY_*`·`VITE_PRIVACY_OFFICER*` 채우기.
2. 개인정보 보호책임자 지정, 개인정보 처리 내부 관리계획 작성 (안전성 확보조치 기준 제4조).
3. 관리자 접속기록을 **월 1회 이상** 점검 (관리자 사이트 → 데이터 → 관리자 접속기록).
4. 관리자 계정 보안: 관리자 사이트를 집·사무실 IP 에서만 열리게 하거나(Caddy `remote_ip`), 2단계 인증을 붙이기 (외부에서 개인정보처리시스템에 접속할 때 안전한 인증수단 — 안전성 확보조치 기준 제5조). 지금은 비밀번호만으로 들어감.
5. 수탁자(토스페이먼츠·iwinv·AWS·메일)와 위탁 계약(약관) 확인, 처리방침의 위탁·국외 이전 표를 실제 사용과 맞추기 (예: S3 를 안 쓰면 AWS 줄을 빼기).
6. 약관·처리방침을 바꿀 때 시행 7일(불리한 변경은 30일) 전에 공지·메일.
7. 백업 파일 암호화·보관 위치 확인 (`deploy/backup.sh`).
