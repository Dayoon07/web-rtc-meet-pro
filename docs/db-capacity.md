# DB 용량: 얼마나 쌓이면 꽉 차나

## 먼저 알아 둘 것: 한도는 30GB 가 아니라 12GB

운영에서 쓰는 **Oracle Database Free(23ai)** 와 로컬의 **Oracle XE 21c** 는 둘 다 **사용자 데이터 12GB** 가 한도입니다
(그 밖에 CPU 2개, 메모리 2GB). 30GB 를 쓰려면 유료 에디션이나 다른 DB 가 필요합니다.
파일(프로필 사진·채팅 첨부·녹화)은 DB 가 아니라 디스크나 S3 에 저장하므로 이 한도에 들어가지 않습니다.

## 한 줄(행)에 드는 크기 (어림값, 인덱스·여유 공간 포함)

| 테이블 | 한 줄 | 무엇이 쌓이나 |
|---|---|---|
| chat_messages | 약 0.4KB (한국어 60자 기준) | 채팅 한 마디 |
| meeting_transcripts | 약 0.35KB | AI 회의록 받아쓴 한 문장 (1년 뒤 자동 삭제) |
| notifications | 약 0.3KB | 알림 하나 |
| login_histories | 약 0.35KB | 로그인 한 번 (1년 뒤 자동 삭제) |
| admin_access_logs | 약 0.4KB | 관리자 API 한 번 (2년 뒤 자동 삭제) |
| meeting_participants · meeting_events | 약 0.25KB | 회의 입장·이벤트 |
| 나머지 (회원·워크스페이스·채널·결제 등) | 합쳐서 회원 1명당 수 KB | 거의 늘지 않음 |

채팅 메시지가 압도적으로 많이 쌓입니다.

## 계산

**12GB ≈ 채팅 메시지 약 3,000만 개** (다른 테이블 몫을 20% 남긴다고 하면 약 2,400만 개).

| 규모 (하루 채팅) | 하루에 늘어나는 양 | 12GB 까지 |
|---|---|---|
| 워크스페이스 10곳 × 20명 × 하루 50마디 = 1만 마디 | 약 4MB | 약 6~7년 |
| 워크스페이스 100곳 × 20명 × 하루 50마디 = 10만 마디 | 약 40MB | 약 8개월 |
| 워크스페이스 500곳 × 30명 × 하루 50마디 = 75만 마디 | 약 300MB | 약 1개월 |

(30GB 라면 위 기간의 약 2.5배)

## 지금 실제로 얼마나 쓰고 있는지 보기

```sql
-- limeet 계정으로 접속해서: 테이블·인덱스별 용량 (MB)
SELECT segment_name, ROUND(SUM(bytes) / 1024 / 1024, 1) AS mb
FROM user_segments GROUP BY segment_name ORDER BY mb DESC FETCH FIRST 15 ROWS ONLY;

-- 전체 합계 (GB)
SELECT ROUND(SUM(bytes) / 1024 / 1024 / 1024, 2) AS gb FROM user_segments;
```

## 꽉 차기 전에 할 수 있는 것

1. 오래된 채팅을 요금제별로 보관 기간을 두고 지우기 (예: 무료 워크스페이스는 1년).
2. 채팅 첨부·녹화는 이미 DB 밖(S3)에 있으니 그대로 두고, 메시지 본문만 오래된 것을 다른 저장소로 옮기기.
3. 데이터가 10GB 를 넘으면 유료 Oracle 이나 PostgreSQL 등으로 옮길 계획을 세우기 (Oracle Free 는 한도를 넘으면 더 쓰지 못함).
